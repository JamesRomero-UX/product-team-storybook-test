# RiskSmart Region deployments - CDK and Tofu Infrastructure

1. AWS Control Tower - update landing zone settings with new regions. Opt in to the new region if required.
2. Bootstrap CDK for account/region combo - new regions should always be a "RiskSmart Region", which use $APP_NAME_FOR_RS_REGION instead of the legacy $APP_NAME. So an example bootstrap would look like, from the `cdk-stack/` directory: `AWS_REGION=ca-central-1 AWS_PROFILE=dev RISKSMART_REGION=true RISKSMART_REGION_PREFIX=uae RISKSMART_REGION_ID=UAE-1  APP_NAME_FOR_RS_REGION=app  TPP_APP_NAME=third-party-portal STAGE=dev-cloud AWS_ACCOUNT_ID=640196420962 BASE_DOMAIN=risksmart.link HASURA_JWT_SECRET=temp TRPC_CONTAINER_BUILD=latest pnpm cdk bootstrap aws://640196420962/ca-central-1`
3. Set up terraform state bucket and locktable for account/region combo, through a setup Cloudformation stack - use `infrastructure/aws/common/cfn_initial_setup.yaml`, e.g. `AWS_PROFILE=ci AWS_REGION=ca-central-1  aws cloudformation deploy --template-file ../../common/cfn_initial_setup.yaml --stack-name ci-terraform-setup-resources`
4. Run in terraform to the CI account, with provider, ECR, default VPC (for sprinters) from your local machine. State will still be stored in S3. After this wee can then run future terraform in with a pipeline. So from the new region's directory - `AWS_PROFILE=ci-account AWS_REGION=ca-central-1 tf apply`
5. Add tofu pipeline (plan/apply) for the new region, to the CI account deploy pipeline (`opentofu-ci-account-deploy.yml`). Use existing steps in that workflow, you'll see how it works easily.
6. Push images to ECR for tasks that don't build their own image in a pipeline yet - `cdk-stack/utils/push-image-to-ecr.sh` - hasura and permit (trpc built in pipeline, integrations currently builds every time). Example: `AWS_PROFILE=ci AWS_REGION=me-central-1 ./push-image-to-ecr.sh permitio/pdp-v2:<version> && ./push-image-to-ecr.sh hasura/graphql-engine:v2.48.11` (Note: find the current `<version>` in `cdk-stack/utils/images-in-use.txt`)
7. Update `container-build-and-publish.yml` to push TRPC containers to the new region. Just add to the matrix in the push step.
8. Add a step to `cdk-dev-cloud-deploy-infra-only.yml` to run in the new region's CDK stacks, on a branch. This pipeline can run against your branch without you having to merge to main, and without having to add a step to the 'main' `dev-cloud-deploy.yml` pipeline (where errors can block others' work). While this is running, when you notice certificate validations from ACM happening (within `CDKCertTenantStack`) - grab the nameservers from Route53 for <region_code>.<stage>.risksmart.link. It's the NS record in the Hosted Zone in that named format. Now go to the root account, and create a new NS record for <region_code>.<stage>.risksmart.link that points to the name servers living in the other account. Now you have delegated the subdomain to the other account.
9. Manually add PDP_API_KEY to permitsecret in secrets-manager for the new region, while CDKTenantStack is coming up (as soon as the permitsecret resource is in CREATE_COMPLETE).
10. After all is green using `deploy-infra-only`, add the new region to `dev-cloud-deploy.yml`. You can now merge your branch, triggering the deploy on main.
11. Repeat steps 2, 3, 8, 9, 10 for staging and production. Replace any references to "dev-cloud" with "staging" or "app". (Note: steps 4-7 are one-time CI setup and are not repeated).
